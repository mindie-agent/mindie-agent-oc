# Session Isolation & Consent-Gated Capture in OpenCode

- **Default-Enabled Tools**: All `remote_*`, component, diagnostic, and `knowledge_*` tools on `mindie-remote-dev` and `mindie-tools` (plus `knowledge_cli.py`) are available on startup without manual session activation; `admission.sqlite3` provisions a default session lease (`not_before=0.0`) on demand when knowledge operations or authorized captures run.
- **Session Context Isolation**: `session.hook("context")` injects cached `SKILL.md` guidance directly in Node.js for top-level sessions (`!parentID && !forkSessionID`), and `shell.hook("create.before")` binds `OPENCODE_SESSION_ID` strictly to shell commands initiated by that session. Subagents and forked sessions do not inherit top-level session context.
- **Consent-First `session.idle` Capture**: On `session.idle`, `opencode_host.mjs` checks `mindie-community.json` (`enabled == true`), `mindie-consent.json` (`choice == "contribute"`), and `project_roots` containment in pure Node.js before spawning `capture_stop.py`. When community sharing is off or outside authorized `project_roots`, zero subprocesses are spawned and zero `admission.sqlite3` files are created. When authorized and in scope, `capture_stop.py` ensures the session lease (`not_before=0.0`), projects redacted public `user` and visible `assistant` text parts read-only (`?mode=ro`) from `opencode.db` into `<state_dir>/transcripts/<sessionID>.jsonl`, and hands off the turn receipt to `mindie_knowledge.loop.cli.capture_hook`.
